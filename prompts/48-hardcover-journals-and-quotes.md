# 48 · Journal entries and quotes between Next Chapter and Hardcover

## Goal

Extend private reading notes into a useful local journal with distinct quotes, and let the reader explicitly bring entries from Hardcover or send selected entries there. Preserve local ownership and make conflicts, visibility, and unsupported API capabilities clear.

## Establish the baseline

Read `AGENTS.md`, `README.md`, `CONTRIBUTING.md`, and `SECURITY.md`. Search team memory in `personal/next-chapter`, fetch relevant records to verify revision/trust/provenance, and check them against current code. Inspect `notes.go`, `hardcover_notes.go`, `hardcover_notes_test.go`, `hardcover_reviews.go`, `hardcover_progress.go`, the sync center, templates, migrations, merge/delete, export/restore, and plan/Undo handling.

Notes already support explicit per-note sharing to Hardcover's `reading_journals` with `event: "note"`. The preview defaults to Only me; local save/edit/delete, status pushes, and progress sync do not share notes. Existing links remember journal, account, and book IDs. Local deletion leaves the remote copy. Optional page/percentage is currently appended to the shared text. Reviews are separate: each local reading has its own review, while Hardcover has one review per book. Do not rebuild those flows or treat a review as a quote. Older prompts saying notes can never be shared describe superseded behavior.

## Research before implementation

- Verify current official [reading journal documentation](https://docs.hardcover.app/api/guides/updatingreadingjournal/) and the [published GraphQL schema](https://github.com/hardcoverapp/hardcover-docs/blob/main/schema.graphql). Record dated sources and exact supported read/write shapes, scopes, pagination, limits, privacy values, timestamps, and deletion behavior.
- Establish whether quotes are a distinct journal event/resource, which fields hold quotation versus commentary, and whether page, percentage, audio position, edition, spoiler flags, or formatting have native equivalents. Do not guess event names or convert quotes into notes silently.
- Distinguish reader-authored notes/quotes from automatic status/progress journal events. Do not import automatic events as private writing or generate duplicate events already created by Hardcover progress/status operations.
- If quote mutations or another direction are unsupported, implement local quotes and the verified directions, show the limitation in the UI, and leave a precise follow-up. Never promise two-way support based only on synthetic fixtures. Do not modify a live account during development without explicit authorization.

## Task

1. **Local journal and quotes.** Reuse existing dated notes where practical; add an explicit entry kind and separate quote text from optional personal commentary. Preserve all existing note bodies, IDs, timestamps, and share links. Support create/edit/delete and optional location without changing progress, reading status, dates, ratings, or queue order. Define bounded lengths and entry counts; preserve Unicode and line breaks. Keep text escaped, or reuse the established safe Markdown renderer only with an explicit format field and compatible migration. No automatic quote extraction or AI submission.
2. **Explicit actions in each direction.** Provide a journal view on the book page with clear Note/Quote labels, local/Hardcover provenance, last successful exchange, and pending changes. Offer reader-initiated “Check journal on Hardcover…” and per-entry previewed import/share/update actions. No remote writes on local save, page load, ordinary library sync, or a timer. Start all selections off. Keep existing note sharing working and explain that the private reason-for-adding field never leaves the app.
3. **Inbound preview.** Fetch only the connected reader's entries for a confirmed linked book; paginate within request budgets and bounds. Show remote content, type, visibility, location, and proposed local result before applying. Never fetch another user's writing. Unlinked books require the existing linking flow; do not create or merge books automatically. Repeated imports must update by remote identity without adding copies. Entries with unsupported types, invalid locations, or oversized content must be explained, never silently truncated or coerced.
4. **Outbound preview and privacy.** Show the exact payload text, destination book/account, existing remote entry, and audience before confirming. New shares default to Only me. Updating a public/followers entry must show its current visibility and require an explicit audience choice; never widen visibility implicitly. Send only the selected writing and mapped metadata. Preserve unsupported fields locally and explain any conversion or omission; do not parse the old appended location suffix as structured data without reliable provenance.
5. **Identity and conflicts.** Key remote mappings by account, book, journal/resource ID, and entry type. Keep a last-exchanged baseline sufficient to distinguish local-only, remote-only, both-changed, and unchanged entries, including privacy and location. Present leave unchanged, use local, or use remote choices with no overwrite selected by default. Do not use newest timestamp or matching text as proof of identity. Identical quotations can be intentional separate entries. Do not retarget mappings after an account switch, relink, or book merge without validating identity.
6. **Safe retries and stale previews.** Re-read local versions, account/book links, and remote content before applying. Double submission, lost responses, partial success, and local edits during a request must not duplicate entries or erase writing. Audit the existing text-match retry strategy: identical content alone must not authorize taking over or changing the privacy of an unrelated remote entry. Use documented idempotency or another verified recovery strategy; if success is ambiguous and identity cannot be proven, show reconciliation instead of blindly retrying creation. Track partial results accurately and require a fresh preview for changed data.
7. **Deletion and detach.** Keep local deletion local. A missing remote entry is a visible conflict, never permission to delete the local original or recreate it automatically. Offer unlink/keep-local behavior with clear consequences. Remote deletion is outside this version; link to Hardcover for managing its copy. Disconnect/Forget Hardcover ids must clear the appropriate sync metadata while preserving local writing and leaving Hardcover untouched. Do not infer remote deletion from an incomplete or failed page fetch.
8. **Privacy and persistence.** Exclude writing from AI payloads, provider logs, errors, routine sync history, CSV exports, and catalog lookup requests. JSON export/restore must preserve local content, kinds, formats, locations, provenance, and safe identity metadata; restored links remain scoped to the matching account/book and are revalidated before use. Handle older exports, duplicate remote IDs, merge/delete, and Undo without losing entries. Merging identical text must preserve separate local entries and must not redirect a remote update to the wrong book.
9. **Integration and failure states.** Reuse the existing client, rate budget, locking, CSRF/authentication, and plan machinery. Bound pages, payloads, and stored previews; never perform network work inside `Store.Write`. Expired tokens, missing scopes, 429s, timeouts, schema changes, and invalid responses must preserve local content and explain what was actually applied. The sync center may link to journal actions, but its ordinary status/rating/progress check must not start transmitting private writing.

## Acceptance criteria

- Synthetic server tests cover notes and supported quote shapes in both verified directions, pagination, account/book isolation, explicit privacy, formatting/location mapping, and unsupported data.
- Repeated checks/imports, duplicate text, both-side edits, remote privacy changes, deleted entries, stale previews, relinking, account changes, double submits, ambiguous creates/updates, and partial failures preserve identity and writing.
- Tests prove local saves/deletes and ordinary sync send no writing; automatic journal events never become authored notes; journal mutations never change progress, status, ratings, dates, pins, or queue order. Distinctive note, quote, and commentary strings stay out of every AI path and routine logs/history.
- Cover migrations, existing share links, older exports, round trips, restore validation, merge/delete, Forget ids, and Undo after newer writing was saved. Append the next available migration; never edit `schema.sql` or shipped migrations. Review `maxRestoreSchema` and document pre-migration backup and rollback.
- Keep the server-rendered, no-JavaScript workflow and existing CSP. Check desktop and narrow mobile in light/dark with synthetic screenshots. Run required checks from `CONTRIBUTING.md`; update README with verified capabilities, privacy, conflict/deletion semantics, and limitations.

Implement the verified feature rather than stopping at a proposal. Finish with resulting behavior, API evidence, unsupported directions, changed files, and validation results. Clearly distinguish synthetic checks from live-account verification.
